Kairo

State-based process monitoring and concept-drift detection for event logs

Installation

Quick start

API

What it does

Kairo describes a process through states computed from a traditional event log, follows how often every state occurs over calendar windows, and turns changes in that mix into drift signals. Every result has a plot_* function for a figure and an abstract_* function for text a language model can read.

Three perspectives

PerspectiveOne row isThe features describe
Intra-casean event its case so far: the activities, their order and the progress
Resourcea calendar window the resources: workload, durations, waits, activity shares and handovers
Inter-casea calendar window all running cases: arrivals, completions, pace, stalls and case attributes

The pipeline

Features → scaling → PCA → states (SOM, k-means or DBSCAN) → trajectories → drift signal. Scaling and PCA can be skipped.

Installation

Kairo ships inside the thesis repository.

From the repository root, this installs kairo as an editable package, so import kairo works in the notebooks and the dashboard:

uv sync

The dashboard starts from its folder:

cd dashboard
uv run streamlit run app.py

API keys

For hosted models, put the key into a .env at the repository root and load it with load_dotenv(). Local servers such as LM Studio or vLLM need none.

ANTHROPIC_API_KEY=...
OPENAI_API_KEY=...
GOOGLE_API_KEY=...

Quick start

Log in, states out, question answered.

Intra-case states

import os
import pandas as pd
import kairo

log = kairo.read_log("log.xes", resource="org:resource", event_duration="event:duration_min")

features = kairo.compute_features_intra(log, sliding_window_size=1)
scaled = kairo.standardize(features, method="minmax")
pca = kairo.compute_pca(scaled, num_components=30)
compressed = kairo.apply_pca(scaled, pca, cut_component=10)

kmeans = kairo.compute_kmeans(compressed, k=5)
states = pd.concat([compressed, kairo.get_kmeans_clusters(compressed, kmeans)], axis=1)

distributions = kairo.compute_state_distributions(states, window="7D")
divergences = kairo.compute_divergences(distributions, divergence="kl", reference="previous")
kairo.plot_divergences(divergences, "kl", "previous").show()

Resource and inter-case states

One row per calendar window, the rest of the pipeline stays the same. The log follows one trajectory through the states, and the windows' vectors can be compared directly.

features = kairo.compute_features_resource(log, window="1D")
# or: kairo.compute_features_inter(log, window="1D", case_attributes={"case:amount": "numerical"})

# scale, PCA and k-means as above, then
trajectory = kairo.get_kmeans_log_trajectory(states)
kairo.plot_kmeans_log_trajectory(trajectory, kairo.compute_kmeans_color_mapping(5)).show()

distances = kairo.compute_window_distances(compressed, distance="euclidean", reference="previous")

Ask a model

messages = kairo.create_messages(
    "anthropic", kairo.DEFAULT_SYSTEM_PROMPT,
    [kairo.abstract_divergences(divergences, "kl", "previous"), "Where does the process drift?"],
    [kairo.plot_divergences(divergences, "kl", "previous")],
)
tokens = kairo.count_input_tokens("anthropic", messages)

llm = kairo.LLMConnector("anthropic", "claude-sonnet-5", api_key=os.environ["ANTHROPIC_API_KEY"])
response = llm.call(messages=messages, max_tokens=16000)
print(kairo.get_response_text(response))

API

Everything is callable as kairo.name, in the order of the pipeline.

A * in a name stands for som, kmeans or dbscan, the three functions then take the same arguments. Dates are text such as "2020-07-01" or "2020-07-01 12:00", or pandas Timestamps. The rows of every frame are events for the intra-case perspective and calendar windows for the resource and inter-case perspectives.

Features

Every function returns one row per event (intra-case) or per calendar window (resource, inter-case). The feature columns are named group:name and come next to time:timestamp, the time of the event or the start of the window, and for intra-case also case:concept:name. These two columns travel along every later step but never enter the maths. A picked feature that needs a column the log does not have raises a ValueError.

A calendar window is a pandas frequency of fixed length, such as "1h", "6h", "12h", "1D", "3D", "7D" or "30D". Windows count from 1 January 1970, so "7D" windows start on Thursdays. Every window from the first to the last event gets a row, windows without events get zeros.

Scaling and PCA

standardize

Scales every feature column, so no column outweighs the others by its unit.

standardize(feature_matrix, method, exclude=["current_act", "past_acts", "act_set"]) -> pd.DataFrame
ArgumentValuesWhat it does
feature_matrixfeatures from compute_features_*The features to scale.
method"zscore" or "minmax"zscore gives every column mean 0 and standard deviation 1, which turns rare columns into large outliers. minmax squeezes every column into 0 to 1.
excludelist of feature group namesGroups left as they are, by default the binary intra-case ones. [] scales every column.

Returns a copy with the scaled columns. A column that never changes becomes 0. Raises a ValueError for another method. To skip scaling, go on with the features as they are.

compute_pca

Fits a PCA, so the explained variances show where to cut.

compute_pca(feature_matrix, num_components=None) -> PCA
ArgumentValuesWhat it does
feature_matrixscaled features, or the features themselvesThe rows to fit on.
num_componentsinteger from 1 to the number of rows or columns, whichever is smaller, or NoneHow many components to fit, None fits all of them.

Returns a fitted sklearn PCA, its explained_variance_ratio_ holds the share of the variance every component explains.

apply_pca

Compresses the features to their strongest components.

apply_pca(feature_matrix, pca, cut_component) -> pd.DataFrame
ArgumentValuesWhat it does
feature_matrixthe frame pca was fitted onThe rows to compress.
pcafrom compute_pcaThe fitted components.
cut_componentinteger from 1 to the fitted componentsHow many components to keep.

Returns the time (and case id) columns with pc_1 to pc_<cut_component>, keeping the index. This is the input of the clustering. To skip PCA, cluster the scaled features directly.

plot_pca_variances

Draws the explained variance of every component as bars.

plot_pca_variances(pca, cut_component=None) -> go.Figure
ArgumentValuesWhat it does

SOM

The clustering functions of all three methods take df, the input of the clustering: the output of apply_pca, or the scaled features when PCA is skipped. Joining the states onto it gives the states frame the later functions take:

states = pd.concat([compressed, kairo.get_som_winners(compressed, som)], axis=1)

compute_som

Trains a self-organizing map. Every cell of its grid is a state, and neighbouring cells hold similar states.

compute_som(df, size=(5, 5), learning_rate=0.5, distance="euclidean") -> MiniSom
ArgumentValuesWhat it does
dfthe input of the clusteringThe rows to learn the states from.
sizetuple of rows and columns, e.g. (3, 3) or (10, 10)The grid, so rows × columns states.
learning_ratenumber above 0, usually 0.1 to 1How far the neurons move towards a row at the start of the training.
distance"euclidean", "cosine", "manhattan" or "chebyshev"How a row finds its closest neuron.

Returns the trained MiniSom. The neurons start on random rows and see every row once in random order, so the cell numbers change between runs.

get_som_winners

Gives every row the cell of its closest neuron, its state.

get_som_winners(df, som) -> pd.DataFrame
ArgumentValuesWhat it does
dfthe input of the clusteringThe rows to place on the grid.
somfrom compute_somThe trained map.

Returns the columns i and j, the cell of every row, with the index of df.
